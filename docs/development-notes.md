# Branch Desk · 本地开发工作台

轻量的本地多项目 Git 分支合并与可选飞书个人排期工具。左侧导航可切换已登记的本地 Git 项目，以及“分支管理 / 我的排期”；窄窗口自动改为顶部导航。每项目连接独立后台，切换不会停止其他项目任务。右侧默认展示分支总览，可对比分支、工作区、服务端口和环境；“进入合并”打开独立审查区，按“来源 → 接收分支”确认方向，再逐文件审查差异。原有本周二/周四上线筛选与批量合并到 pre 保留。不会自动为每个 worktree 启动编辑器、开发服务或文件监听器；后台和开发服务仅在明确点击启动时运行。

### 多项目与设置

导航区的项目菜单可切换项目；旁边的设置按钮用于添加本地 Git 根目录、修改名称、设为默认或移出登记。移出仅删除工作台登记，不删除代码、分支、worktree 或停止后台。网页可输入绝对路径，macOS 应用可使用目录选择器。未运行的项目会显示状态，需要单独点击“启动工作台”。切换前会检查正在进行的操作、预览及未保存编辑。

项目设置保存在当前用户配置目录 `~/Library/Application Support/Branch Desk/`（其他平台为 `~/.config/branch-desk/`），不写入业务仓库或签名应用包。旧版 `state/operations.sqlite3` 在首次新版启动时复制到用户配置目录，原文件保留；排期草稿仅从原飞书空间迁移。Git 操作记录按仓库、飞书需求关联及开发会话按仓库与飞书空间隔离。更换飞书空间不会继承同编号需求的旧关联。

服务自动启动支持 bibase、直接 Vite 脚本的 Vue 项目及上述 Gradle/Spring Boot 后端；其他 Git 项目仍可管理分支与 worktree。设置可选择 Vite 脚本、模式、自动或固定端口，以及项目支持的测试后端；自定义联调地址仍只对本次启动生效。运行中后端按进程分别显示启动记录、运行时识别或配置推断来源；“重新检查”会再次探测，配置推断不代表已核实实际进程。飞书可按项目关闭；启用前须从当前 MCP 连接读取空间、需求类型、字段和样例需求的本人节点并保存验证。当前仅复用已有飞书身份，不自动新增账号或认证方式。

需要 Python 3.9+、Git 2.38+ 和现代浏览器。优先直接使用 `/usr/bin/git`；没有系统 Git 时才使用 PATH。Vue 3.5.13 已附带，无需 npm install，页面资源无需联网或 CDN；刷新远端需能访问 origin。自动冲突处理需要已安装并登录的 Codex CLI（`codex` 在 PATH 中）以及已安装的 Codex/ChatGPT 桌面端；使用你的现有模型与认证配置。

macOS 双击 `启动合并工具.command`，粘贴仓库或任一 worktree 的完整路径，工具会自动用系统默认浏览器打开**完整地址（含 # 后的会话凭证）**；如果打开失败，可手动复制终端中的完整地址。不要将这个地址分享给别人。保持终端打开，Ctrl+C 关闭服务。

也可以在本目录运行：

```sh
python3 server.py --repo '/你的/仓库路径'
```

默认自动选空闲端口，只监听 `127.0.0.1`。可用 `--port 8765` 固定端口。每次启动生成新凭证；启动时打开的完整地址会更新同一浏览器中的本地凭证。之后关闭标签页或浏览器，再访问同一地址（例如 `http://127.0.0.1:8765/`）会自动恢复连接；已打开的旧标签页也会在下次请求时使用更新后的凭证。不同浏览器、隐私窗口或清除网站数据后，需要再用启动器提供的完整地址授权一次。浏览器禁止持久存储时保留地址中的凭证，避免刷新时丢失；请勿分享完整地址。服务关闭后仍需启动服务；保存凭证不会自动启动服务。可以为不同仓库分别启动工具。

更新此工具后，请先在旧终端按 Ctrl+C 关闭旧进程，再重新运行启动器，以载入新的后台接口。

### macOS 独立应用

可将工作台作为独立的 **Branch Desk.app** 使用：拥有自己的窗口、Dock 图标和 `⌘Tab` 入口，切换 Codex 聊天时仍保留当前页面。内容继续使用现有 Vue 页面，系统 WebKit 承载，无需安装 npm 依赖。

- 打开应用时只检查并连接默认项目的后台，自动取得当前端口和连接凭证；导航区可切换其他已登记项目。未运行时显示“启动工作台”，点击后才启动；连接不确定时保留错误，不重复启动。
- `⌘W` 或窗口关闭按钮仅隐藏窗口，点击 Dock 图标恢复原页面；`⌘Q` 退出应用，后台服务与任务继续运行。可将应用手动拖入 Dock 常驻。
- 顶部菜单栏常驻分支图标：左键直接显示工作台，右键以系统菜单栏按钮的标准方式展开“显示工作台 / 隐藏工作台 / 退出 Branch Desk”，避免菜单浮在图标上。隐藏、最小化或关闭窗口后仍可从这里找回原页面；图标自动适配系统深浅色。退出应用会移除图标，下次打开应用后恢复。
- 独立窗口与浏览器共用响应式侧栏，分支总览与合并审查按窗口剩余高度滚动；窄屏内容仍可滚动，代码差异、排期表格及弹窗保留必要滚动。主内容可 Tab 聚焦后使用键盘滚动。
- `⌘R` 刷新页面；后台重启后通过菜单“窗口 → 重新连接工作台”取得新地址。刷新、重连和退出会先检查未完成操作，必要时弹出确认。返回应用时仅在安全状态下读取当前 Git 信息，保留预览、弹窗与排期编辑。
- 复制按钮使用系统剪贴板；飞书 HTTPS 链接交系统默认浏览器，Codex 会话链接交 Codex 打开。应用内只加载已核验的本机工作台地址。
- 常用分支按 Git 仓库保存在本机 Branch Desk 用户配置中，重启换端口或切换浏览器后仍可读取；首次升级会导入当前地址可读取的旧收藏，其他旧端口的浏览器存储无法自动导入。最近使用、审查位置和排期草稿仍保存在各浏览器的当前地址下，换端口后不会自动迁移。退出前请完成或保存当前编辑。

本机构建命令（需要 macOS 13+、Xcode Command Line Tools 和 Python 3.9+）：

```sh
python3 macos/build.py --repo '/你的/仓库路径' --output "$HOME/Applications/Branch Desk.app"
```

输出路径已存在时停止，不覆盖原应用。构建会编译当前 Mac 架构、生成图标、执行无界面的策略自检并使用 Branch Desk 专用本地证书签名，不启动服务或打开窗口；可用 `'/完整路径/Branch Desk.app/Contents/MacOS/BranchDesk' --self-test` 再次运行纯策略自检。

此版本绑定构建时的工作台和 Python 安装路径，构建时指定的仓库仅作初始项目与默认项目失效时的回退入口；其他项目运行时登记和选择，无需重新构建。沿用本机 Codex 配置，不内置账号或临时连接凭证。移动工作台或更换 Python 时应重新构建；移动 `.app` 本身不影响绑定。专用签名不使用公司证书，不修改系统信任设置，未作 Apple 公证，不作为可直接分发到其他 Mac 的完整安装包。编译与自检不代替真实窗口、输入法及跨项目连接验收。

macOS 的“文稿”“桌面”访问由系统授权。旧版临时签名的身份随重建变化；专用证书将后续版本绑定到相同身份，避免由升级换签导致重复授权。从旧版迁移后仍可能需要你允许一次，应用不能自动点击或绕过。请保留本机专用签名资料，后续构建不要删除或重建证书；如果在系统设置中撤销访问、证书更换或系统重置权限，仍需重新授权。同一个未更新的应用若继续重复询问，应再检查系统权限记录，不能仅凭签名检查认定已完全解决。

构建时会记录当前可用的 Codex、Node 和 npx 命令目录，使 Finder 启动的应用也能使用 nvm 等工具安装的 Node。升级或移除这些运行环境后应重新构建。若“我的排期”提示找不到连接命令，请先确认构建终端可运行 `codex`、`node`、`npx`；更换应用后重新打开，并在明确关闭原后台后启动一次，已运行的后台不会因刷新页面或重新连接而更换 PATH。应用沿用原 Codex 配置目录，不自动切换账号或复制授权凭证。

6. 无冲突时，检查暂存区、运行项目规定的检查，点击合并方向卡片中的“检查并提交”，预览暂存文件和差异、填写提交说明，再点击“确认提交到分支”。工具执行项目 Git hooks 后创建本地合并提交，不自动暂存、不推送。工具重启后也能识别已有待提交合并。有冲突时，工具自动在**当前目标 worktree** 启动 Codex 处理任务，任务结束、CLI 完全退出后，再用 `codex://threads/<thread-id>` 打开对应桌面会话。页面自动刷新处理状态，也提供打开会话的链接。Codex 负责对照双方内容解决冲突；工具核验后只暂存本次原始冲突路径，不创建提交、不推送。

### 单独提交和推送当前分支

### 合并提交说明

合并提交默认使用 `merge: 合并 来源分支 → 目标分支`，目标需求分支的 M-ID 仍放在描述开头。正文列出完整分支、合并前 HEAD、来源 SHA 和本次新增的普通提交（最多 20 条，并明确提示截断）；不会重复列入目标已经包含的提交。单次、批量和修复后继续提交使用同一规则，单次提交仍可编辑并重新预览。来源优先使用与合并前 HEAD、来源 SHA 相匹配的操作记录；记录缺失时仅使用唯一指向来源提交的分支，无法唯一确定则显示 SHA，不猜测分支。

- 待处理列表是检查时的快照，非实时监控。读取失败显示未完成检查及原因，不视为没有问题；快捷信息请求 15 秒超时后可手动重试。点击事项重新核对现场，提交、合并、释放和推送继续使用原有确认流程。

页面请求期间显示已用秒数，结束后保留最近一次操作名称和耗时；结果或错误仍在原反馈区展示。历史 Git 记录显示当次耗时，服务中断记录的时长只表示到服务重启确认中断为止。合并预览、提交及推送的主要按钮展示不可用原因，忙碌、冲突、未提交内容及来源未选等状态均须先处理。

“清理候选”只读初筛当前仓库的已登记 worktree：排除启动目录、当前选择、常用目标、master、分离 HEAD、缺失/锁定/登记异常、有本地改动或 Git 操作的工作区。读取失败保留并列出原因，需求读取或冲突处理期间不扫描。候选仅代表通过基础检查，未判定分支是否已经交付；点击“检查释放条件”仍调用既有完整预览，核对忽略文件、子模块、隐藏索引标记、嵌套目录与进程占用，再由用户确认释放。没有一键批量删除。

### 排期与审查效率

- 排期行保留读取/打开开发任务和进入关联分支的常用入口，与“更多”保持同一排；“填写 / 调整”、修改关联、重新读取、旧会话和需求详情收在紧凑的纵向浮层中，不撑高表格行，也不被表格滚动区域裁切。使用键盘 Enter/空格展开，Esc 收起并回到入口；选择操作、点击外部、滚动表格或页面、调整窗口、切换模块时收起，菜单内部仍可滚动。长分支与状态摘要最多显示两行，悬停可看完整内容。
- 已排期仅展示“前端开发”节点，技术设计及其他节点不进入列表、筛选计数和已加载排期的快捷入口；查询估分仅汇总当前日期范围内的前端开发节点。排期支持“全部 / 未完成 / 今日排期 / 已关联分支”筛选，数量受当前搜索条件影响，仅覆盖已加载日期范围。“今日排期”按北京时间的起止日期判断；关联读取失败时不把未知情况当作未关联。查询区显示最近成功读取时间及对应范围；失败保留上次数据和时间。
- 编辑有改动时，切换模块使用统一弹窗提醒并保留表单；取消编辑会确认是否放弃，并清除此节点草稿。保存失败保留表单与草稿，保存成功后清除草稿。已有草稿未恢复或删除前不覆盖它，也不能直接提交它。
- 合并页标题旁的图标可收起或展开分支列表，保留选择、筛选及搜索状态。排期页保持全宽。
- 操作记录可搜索分支、来源和目录，按操作类型筛选，或仅查看失败、冲突、中断和结果未确认的记录。筛选只影响展示，执行中记录的刷新保持原有行为。
- 已排期列表的“版本上线（计划）”展示需求关联的规划版本及其预计发布日期；多个版本分别显示，也可按版本名称或日期搜索。排期先展示，再分批读取版本；未关联版本、未填写发布日期和读取失败分别提示。日期来自飞书版本字段，不根据版本名称或开发结束日期推算，也不代表已经发布。新增后台接口需明确重启后生效，单独刷新只能更新页面。
- 顶部显示当前前端版本；页面可见时每分钟检查一次，重新聚焦时也会检查。发现新版只提示手动刷新，存在编辑或进行中的操作时暂缓。此检测读取静态首页，无需重启后台；后续前端更新需同步修改 `web/index.html` 的 `branch-desk-build` 版本标记。后台接口更新仍需重启服务。

## 文件选择与操作栏

当前分支文件选择提供“全选可暂存文件”，支持全选、取消全选及部分选中状态，并显示已选数量。仅选择未暂存或未跟踪文件；纯已暂存文件保持勾选并随提交包含，取消全选不会取消已有暂存。选择仅改变勾选，仍须点击“暂存所选并预览提交”才暂存。

代码合并页将预览合并、提交当前分支（或检查并提交合并）和推送当前分支集中到底部操作栏；打开预览后，同一区域显示当前步骤的取消和确认按钮。桌面宽度下，仅内容区滚动，操作栏持续可见，打开预览时自动定位到审查区域；文件和差异列表仍独立滚动。窄屏操作栏允许换行并贴住滚动区域底部。合并、暂存、提交、推送仍分别确认，沿用各自保护和 hooks。

## 提交后的推送

合并方向卡片提供“预览推送”按钮。完成提交、工作区干净且没有进行中的 Git 操作时，点击后先联网读取实际 push URL 上的同名分支，展示远端地址、目标引用和待推送提交；再点击“确认推送到远端/分支”才写入远端。提交本身不会触发推送。

- 禁止 master、分离 HEAD、异名上游、mirror、多个 push URL 或异名 push refspec。核对目标分支第一父链新增提交的说明，不改写合入历史；不合规则报告并停止。
- 已有同名远端分支只允许快进；远端有本地未整合的提交时停止，需先刷新远端引用并处理。没有上游时默认 origin，首次确认推送才创建同名远端分支并设置同名上游。
- 固定使用显式 `HEAD:refs/heads/<当前分支>`，不强推、不额外推送标签或子模块，保留项目 hooks。仅该次 push 关闭 Trace2 扩展事件，防止本机 Git AI 监听器另行推送 notes/标签；不改全局配置。预览 10 分钟有效且仅使用一次；分支、HEAD、工作区、配置或远端变化时重新预览。
- 推送后回读实际 push URL 核对提交。失败或结果不确定时不自动重试；先核对远端实际状态。推送时暂停其他工具对同一 worktree 的写入；工具不能锁住其他 Git 客户端。

## 批量合并与同步

“代码合并”页面提供两个批量入口：

- **批量合并**：搜索并多选来源分支，选择一个目标；按点击顺序加入，可用上下箭头调整合入顺序。
- **同步到多个分支**：选择一个来源，多选接收分支并调整顺序；默认来源为本地缓存的 `origin/master`。上线后先刷新远端引用，再预览同步，确保使用所需版本。

选择与排序区的“常用组合”可按仓库在当前浏览器保存最多 8 组名称、模式、分支引用及顺序。只保存选择，不保存预览、提交号或执行授权；点击“填入”后仍须重新预览确认。分支已删除、目标为 master 或工作区缺失时拒绝填入；浏览器存储不可用或损坏时提示，保留手动操作与原存储，不自动覆盖。移除组合不删除分支或 worktree。

弹窗分为“选择与排序”“预览确认”“执行结果”，当前步骤独立展示，列表在内部滚动，底部操作固定可见；返回调整保留已选分支和顺序。预览时只读核对方向、固定来源提交、候选提交数及文件概览；最多 30 项，10 分钟失效。后续来源的概览基于预览时的目标，不预测前序合并后的最终结果。目标必须是干净的非 master 分支；未检出分支在执行时按既有规则创建 worktree 并初始化 Husky，失败保留现场。

为了继续下一轮合并，批量模式需要完成每一轮的本地合并提交。**点击“确认合并并本地提交”后**才执行：逐项合并 → 必要时交给现有 Codex 解决冲突 → 检查冲突处理结果 → 执行正常 hooks 创建本地合并提交 → 下一项。来源已包含时跳过，不制造空提交。不会自动推送或更新远端 master；普通单次合并仍停在待提交状态。

队列在后台串行执行。弹窗显示逐项进度、本地提交和冲突会话，全部完成时页面提示结果；关闭弹窗或刷新页面仍会继续，重新打开可查看进度。工具执行期间阻止其他合并、目标准备、提交、推送和远端刷新入口；外部 Git 客户端无法被锁住，请暂停对相关 worktree 的写入。

任一目标/来源变化、脏工作区、冲突处理失败或 hooks 拒绝都会停止后续项，保留已完成提交及当前暂存/冲突现场，不自动回退或重试。“停止后续任务”同样保留当前命令/冲突处理的现场，不终止正在执行的 Git 命令；正在运行的 Codex 冲突处理可能继续完成。重启工具不自动恢复队列，请先核对 Git 状态后重新选择尚未完成的项。

失败项若仍保留原分支、HEAD 和合并来源，会提供 **使用 Codex 修复**：确认后把本次错误及合并文件交给现有 Codex CLI，在原 worktree 中分析并修改代码；不暂存、提交、推送，也不修改 hooks 或削弱校验规则。修复期间暂停其他写操作，进程退出后可打开对应会话。原始错误和任务日志保存在本机私有临时目录，不写入操作历史数据库；修复范围之外的已跟踪内容、索引、引用、配置和普通未跟踪文件变化会阻止自动确认，不自动回退。

失败项的“使用 Codex 修复”和“检查修复并继续”会在当前结果卡片内显示确认、读取进度及错误，不必返回列表顶部查找反馈。成功生成续跑预览后仍跳转到审查区；旧 Codex 结果是当时记录，继续前以重新读取的 Git 现场为准。超出原合并范围的改动、分支或配置变化仍会阻止旧批次续跑，需重新审查当前工作区，不自动回退或放宽保护。

若原合并已在其他入口提交或中止，旧批次的修复、续跑预览和确认续跑都会先识别失效现场，提示刷新进度并重新选择尚未完成的分支，不再因缺少 `MERGE_HEAD` 显示 `fatal: Needed a single revision`。此校验不暂存、不重复提交、不重放后续任务。2026-11-04 的后台修复需明确授权重启工作台后生效；重启不会恢复旧队列。

修复完成或自行处理后，点击 **检查修复并继续**，审查将暂存的文件、最终差异、提交说明及剩余项，再确认继续。工作台只暂存原合并范围，重新执行正常 hooks，完成当前提交后继续后续项，保留已完成项；预览十分钟失效，内容或其他目标变化时停止。提交已经创建但结果未确认时不提供重试入口，避免重复提交。旧版服务和重启前的队列不补建恢复凭证；Git 现场仍保留，可从分支重新检查并提交。带长编号的需求分支按项目 hook 的前十位 M-ID 生成提交说明，避免编号漏识别导致 hook 拒绝。

两种模式全部合并完成后，结果弹窗提供**批量推送**：按本轮目标顺序去重，展示各自远端地址、同名目标引用、HEAD 和待推送提交，点击“确认批量推送到同名远端”后才依次写入。多来源合入一个目标时只推送该目标一次；同步到多个分支时逐个推送接收分支。保留正常 pre-push hooks，禁止 master、异名上游、模糊推送配置或强推；远端已一致的项核对后跳过。首次推送可创建同名远端并设置同名上游。

合并完成后的 HEAD、工作区、有效推送配置或远端变化会阻止推送；首次推送产生的已完成分支上游配置不会使后续分支预览失效。失败或结果未确认即停止，不回退已成功的远端、不自动重试。结果区保留成功、失败和未执行项；核对实际远端后，可重新预览，已一致的项会跳过。合并与推送分别确认，合并完成不会自动触发推送。

## 我的排期

飞书连接优先保留启动环境及 MCP 配置中的显式代理设置；未显式设置代理时，读取系统已有的 HTTPS 代理，并遵守飞书域名的系统绕过规则。仅给飞书子进程启用 Node 环境代理，不修改系统 DNS、全局 Codex 配置或认证；需 Node 支持 `NODE_USE_ENV_PROXY`（本机 Node 22.22.1 已验证）。只开启系统代理、后台 Node 没有使用代理时，仍可能因直连 DNS 失败而无法读取排期。后台连接代码更新后需重启生效。

复用本机 Codex 配置中已启用、已授权的 `FeishuProjectMcp`（stdio 连接）。当前接入“平台事业部”，身份由连接实时查询；需要 Codex CLI 和该 MCP 启动命令所需的 Node/npx。无需在页面粘贴 Token，也不会把 Codex 配置或凭证打包进工具。进入此模块才连接飞书；连接失败不会影响代码合并。 配置使用 npx 时，工作台仅从本机 npm 缓存启动已安装的 MCP，不在每次连接时检查 npm 仓库；飞书 API 仍正常联网。首次使用或缓存被清理后，需先在 Codex 中正常连接一次以安装该工具，不修改已有认证或工具权限。

1. 切换到“我的排期”，默认读取北京时间本周的已排期任务。可切上一周、下一周，或选择起止日期查询，最多 90 天。显示任务、节点、日期、估分和完成状态；支持搜索，未完成任务优先并按开始日期排序。未排期任务不抓取、不展示，也不显示其数量。
2. 点击“填写 / 调整”，实时读取节点的本人独立排期。填写开始日期、结束日期、估分和实际工时；0 会保留为 0，留空表示未填写。起止日期必须成对填写或清空。
3. “清空本人排期字段”先清空表单，不立即写飞书。也可仅清空某项；预览会明确显示哪些值被清空，并保留其他字段（包括 0）。
4. “预览修改”展示原值和新值；再次点击“确认保存到飞书”才写入。表单打开后或预览后数据/负责人变化会阻止保存，需取消并重新打开；预览 5 分钟有效且仅能使用一次。
5. 保存通过个人 `schedules` 更新，不更换节点负责人、不提交节点流转；成功后重新读取并比对四个字段，再刷新已排期列表。移动或清空排期后，任务可能从当前日期范围消失。
6. “需求详情”通过实际工作项类型定位原页面。浏览器拦截新窗口时，工具会先准备链接，再点击该行“需求详情”即可。

“我的排期”内可切换到 **版本上线**，按北京时间查看本周全部、本周二、本周四上线需求，或选择上线日期范围查询（最多 90 天）。范围按本人负责的“前端开发”节点及需求所关联规划版本的计划发布日期查询，与开发排期区间独立，因此会包含往周开发、本周上线的需求；多版本需求按需求去重、分别展示匹配范围的版本。读取失败保留上次结果及范围，不将不完整数据当作空列表。

上线列表支持搜索、逐项勾选及“全选可合并需求”。先关联本地需求分支，未关联的需求会列出但不能勾选。点击 **批量合并到 pre** 时重新核对本机关联和分支，去重来源后填入原批量弹窗，最多 30 个分支；目标优先本地 `pre`，仅有远端时使用 `origin/pre`。关联变化、分支不存在或缺少 pre 会阻止继续；查询、选择和填入弹窗不创建工作区或执行 Git 写入。仍需预览并点击“确认合并并本地提交”才执行，推送继续单独确认。切换日期、搜索或关联变化会清空勾选，避免带入不可见任务。新增上线查询接口需重启后台后启用，前端版本为 `2026.10.27.1`。

每个任务可“关联分支”：搜索当前仓库的本地非 master 分支，点击“确认关联”后仅保存本机关联；唯一匹配 `M-任务编号` 或 `M-任务编号-…` 的分支会预选，仍需确认。“进入分支”重新核对关联、分支和工作区，只读取状态；没有可用 worktree 时先定位分支，再由原入口单独确认准备工作区。关联失效、分支已删除或工作区切换分支时提示，不自动创建、切换或合并。解除关联保留分支和会话。

关联与开发会话按仓库及飞书空间存于用户配置目录下的 `operations.sqlite3`，不会写入飞书或业务仓库。已保存的开发会话可从排期行或关联分支顶部打开；会话跨重启保留，升级前的内存会话不补录。关联仅用于导航，不改变“读取需求并生成计划”的项目根目录、skill 流程及实施确认。

当前可编辑的是**本人负责节点的独立排期记录**。多人共享节点且无本人独立记录时阻止编辑；其他记录请在飞书详情操作。创建/删除任务、完成/回滚节点不在此版范围。

## 保护与限制

- 仅操作启动时指定仓库的分支与已登记 worktree。可经确认按需创建目标 worktree；仅远端分支会新建同名本地分支并绑定同名上游。既有工作区不切分支，不删除 worktree，仅确认推送时更新同名远端分支，首次推送可绑定同名上游；不修改既有上游配置；目录已存在、符号链接或嵌套其他 worktree 时拒绝创建，不自动覆盖或清理失败现场。
- 远端刷新相当于限定范围的 `git fetch --prune origin`：强制限定到 `refs/remotes/origin/*`，不更新或删除本地分支、标签，不递归更新子模块，不自动 merge、pull 或 push。需要 origin 已配置且认证可用；认证失败会显示错误，不会继续合并。
- 分离 HEAD、异名上游、未提交/未跟踪文件、正在 merge/rebase/cherry-pick 等情况均阻止合并。没有共同祖先的历史不支持。
- 合并前显式检查来源写入路径与本地未跟踪/忽略文件的碰撞，另开启 Git 忽略文件覆盖保护；不自动 stash，不自动应用 rerere 的既往冲突解法。
- 预览绑定分支、HEAD、来源 SHA、状态与上游，10 分钟失效，只能执行一次；变化后需重做预览。
- **合并、提交、推送及 Codex 冲突处理期间不要在 VS Code、终端或其他工具同时修改该 worktree，也不要在同一 Codex 会话重复发送处理请求。** 后台处理期间阻止新的合并和远端刷新；工具无法锁住其他 Git 客户端及编辑器。
- 提交仅支持没有未解决冲突的待提交合并（MERGE_HEAD），不支持普通工作区提交。存在未暂存的跟踪文件改动时阻止提交；未跟踪文件保留，不自动加入。提交预览绑定分支、HEAD、暂存内容、合并父提交与 Git 配置，10 分钟有效且仅使用一次；变化后需重新预览。标题遵守个人约定的 type: 描述、108 字符与需求分支 M-ID 规则，实际 hooks 继续执行，不跳过。hooks 拒绝或结果不确定时显示错误，不自动重试；若 hooks 改写了已提交内容或说明，明确报告提交已创建，不自动回退或修订。
- 没有手动冲突编辑器或撤销按钮。冲突由 Codex CLI 后台处理，在桌面端打开的是这次 CLI 任务的对应会话；不复用或打断其他已有聊天，冲突处理不创建新 worktree。
- 如需放弃尚未提交的合并，请先确认并保留合并开始后新增的人工修改，再自行在目标 worktree 运行 `git merge --abort`。不要在未检查修改时直接撤销。
- 已结束的合并结果卡片是本次操作记录，当前状态以“刷新当前工作区状态”为准。工具重启后 Git 合并状态仍保留，不会自动恢复或继续操作。
- 在 Codex 会话或编辑器修复后，Git 可能仍显示 `UU`。单次合并可点击“检查修复结果”，审查当前冲突文件相对目标 HEAD 的差异，再明确确认暂存这些文件；之后使用独立的“检查并提交”。检查会拒绝残留冲突标记、符号链接、子模块和隐藏索引标记，预览绑定内容与现场，10 分钟内仅能确认一次。刷新状态始终只读；此检查不代表业务功能验收，不自动提交或推送，也不加入其他文件。已由外部暂存的修复按当前 Git 状态进入待提交，原 Codex 失败信息仅作为上次处理记录。
- 仓库自定义合并驱动、Git 配置按 Git 本身执行；如已配置 Git AI/Trace2 等扩展，扩展可能自行更新 notes 等元数据。合并工具不安装/构建业务项目；Codex 冲突处理会按任务运行必要的已有静态检查或相关测试，不启停业务服务或操作浏览器；需求审查按上述接口读取、原型静态分析的只读流程执行。子模块内容不会自动更新。仅用于你信任的本地仓库。

## Codex 冲突处理边界

- 使用 `codex --no-daemon -a never exec --sandbox workspace-write -C <目标路径> --json`，复用现有认证与模型设置，不启用绕过审批或沙箱的参数。工具开启单独的冲突处理任务，CLI 的执行可能消耗你现有账户或配置提供方的用量。
- 明确调用并实际读取本机 `dev-command-workflow` skill，复用其中的冲突处理流程；提示词限定原始冲突路径，要求对照 stage 1/2/3 和上下游保留双方应有行为，不批量选择一边，不猜业务契约。Codex 只编辑文件，由工具完成最后的限定路径暂存；skill 缺失时保留现场并提示，不静默替换流程。
- 桌面会话最终返回中文 Markdown：先说明处理结论，再列文件与双方保留功能、实际检查、阻塞或注意事项和下一步。机器状态单独写入本次私有日志目录的 `result.json`，最终回复保存为 `report.md`，不再强制把 JSON 显示为聊天回复；冲突和失败修复共用这一返回方式。状态或报告缺失、格式无效时不自动暂存。会话中的“已解决”仍需工作台保护检查与限定路径暂存，最终暂存状态以工作台为准。
- 检查区分本次新增失败、经双方版本或基线证实的原有问题，以及未验证项。仅经证实与本次无关的原有问题可单独列为警告；必要检查未完成或失败来源不明仍保留阻塞，不修改范围外文件或削弱校验。
- 执行前保存原始索引和范围信息。完成后核对分支、HEAD、MERGE_HEAD，以及冲突范围外的索引、跟踪文件 diff、可见未跟踪状态、分支/远端跟踪/标签引用及 Git 配置。发现变化就停止自动暂存，不擅自回退用户或 agent 的改动。此检查不构成对整个磁盘的安全隔离，仍需信任当前仓库与 Codex 配置。
- 只有 CLI 正常完成、明确返回已解决、保护检查及 diff 检查通过、冲突标记消失后，才暂存原始冲突路径，并再次确认冲突索引为空。显示完成仍需你审查代码和模型报告的检查结果。
- 找不到 CLI、登录或网络失败、权限不足、业务语义不明确、仍有冲突或保护检查失败时，页面显示失败并保留现场。请在对应 Codex 会话继续核查，或自行处理；工具不会静默改用整边覆盖。
- 每次执行最多 30 分钟，超时会停止该次 CLI 进程并保留已产生的改动。关闭本地工具也会终止其启动的 CLI 进程；重新启动工具不会自动重复执行旧任务。
- 私有任务日志在系统临时目录 `worktree-merge-codex-*` 中（页面会显示完整路径），包含原始索引、范围信息、提示词、JSON 事件和最终报告。可能含源代码与路径，不要公开分享；临时目录可能被系统清理，Codex 会话按 CLI 默认方式持久保存。
- 冲突处理和失败修复的聊天标题均由工作台在 CLI 完全退出后，通过 App Server 的 `thread/name/set` 设置并用 `thread/read` 回读核验，再自动打开会话。标题移除分支的 `M-数字` 前缀及连接符，保留需求名称与业务标签；本轮提示词明确将聊天改名交给工作台收尾。改名失败会显示警告并保留日志，处理结果与会话打开流程继续执行。冲突检查及暂存结束后才打开会话，并显示可点击链接；桌面端打开失败时保留链接。会话通过官方深链接打开。

## 释放附加 worktree

主工作区、工具启动目录、master、分离 HEAD、Codex 托管目录、锁定/异常登记、Git 操作、未提交/未跟踪文件、隐藏索引标记、子模块和目录内其他 worktree 会阻止释放。忽略文件也阻止释放，须自行保留处理；仅经已安装 Husky 8 原文件比对的标准 `.husky/_/husky.sh` 与 `.gitignore` 可作为可再生文件随目录移除，预览中会列出。

预览 10 分钟有效且单次使用；确认前重新检查分支、HEAD、登记、本地文件和进程占用。本工具的开发读取/批量/冲突任务运行时禁止释放。通过 `lsof` 检查以目标目录或子目录为 cwd 的进程，失败时阻止释放；无法识别所有外部编辑器或其他客户端的并发写入，请先暂停对应任务。释放失败保留错误，不自动重试。测试仅使用临时仓库，不释放业务 worktree。

分支行只保留左侧箭头作为“详情与操作”的统一入口，同时只展开一个分支；移除右侧“更多”入口及第二层操作区。展开区保留完整分支、工作区目录、后端环境、PID 和服务日志，直接提供更新、设为常用、复制目录、设置联调地址、释放 worktree 及删除本地分支。目录和联调按钮各保留一处；名称旁的复制图标保留，不重复放置“复制名称”按钮。Esc 收起详情并将焦点返回该分支箭头，筛选隐藏该分支时自动收起；点击详情外部不再意外收起。复制完整分支名（仅远端项不含远端前缀）和目录不会切换或创建 worktree，成功和失败都会提示。

已有 worktree 的分支行在启动操作前提供“对话”。点击后重新核验登记目录与当前分支，以仓库主目录匹配 Codex 中对应的已有项目，预填所选 worktree 的完整路径、分支核对要求及“打开「对应分支」，进行调整：”，提示需手动发送。新对话初始目录为项目主目录，后续处理按提示中的 worktree 路径执行。从 worktree 启动工作台也使用同一仓库主目录匹配项目。master 也可打开对话。

“更新”对已有可用工作区的分支开放，包括本地 master；先读取现场并展示分支、目录及 origin 同名来源，明确确认后只抓取该远端分支并快进更新当前行的工作区，不切换其他工作区。master 的“更新”仍只允许从 origin/master 快进更新；“进入合并”、本地合并和提交已开放，仍禁止推送，不写入远端 master。已有上游必须是 origin 同名分支；未设置上游时读取 origin 同名分支但不自动绑定。已一致或本地领先时提示无需拉取并保留本地提交；历史分叉、脏工作区、进行中的 Git 操作、隐藏索引标记或覆盖本地忽略文件时停止，不自动 stash、reset、rebase、创建合并提交或推送。操作预览未完成时不可更新，失败不自动重试。`2026.11.02.2` 包含更新接口，`2026.11.02.3` 将详情与操作合并为一个展开入口；`2026.11.02.4` 允许本地 master 更新，后台新增独立的更新阻塞检查，须明确授权重启 Branch Desk 后重新连接工作台才完整生效。旧后台缺少 master 更新支持或更新接口返回 404 时，提示先重启后台并重新连接，不自动重试更新。

释放受阻时，弹窗保留分支、目录和原始原因，并提供“复制排查信息”“复制目录”“重新检查”。排查信息可粘贴到任意 Codex 对话，默认先只读核对并等待确认，不自动发送或清理；剪贴板不可用时可展开文本手动复制。重新检查只更新释放预览，仍须单独确认才释放。

### 强行释放忽略文件

普通释放受阻后可点击“强行释放…”，重新预览将丢弃的忽略文件/目录、类型及条目数。点击“继续强行释放…”后弹出二次确认，明确展示工作区目录、将删除的本地忽略文件和链接范围；点击“确认删除本地文件并释放”后才移除，无需输入分支名，不自动备份；本地分支、提交和远端保留。符号链接只移除链接，保留外部目标。此模式只绕过忽略文件拦截，未提交/未跟踪改动、进行中的 Git 操作、隐藏索引标记、锁定、进程占用、子模块、嵌套 worktree 或忽略目录中的 Git 仓库仍禁止释放；不使用双重 force 或跳过这些检查。

确认前复查分支、HEAD、登记和忽略文件元数据指纹；发现预览后新增、替换或改写的本地文件会阻止操作，须重新预览。此检查不能锁住外部写入，操作时请暂停其他工具。每次清单最多检查 20 万项/15 秒，超出时停止并要求终端处理，不静默跳过；不读取依赖文件正文。此功能测试仅使用临时仓库，不释放业务 worktree。

## 删除本地分支

本地分支详情区提供“删除本地分支”，先检查并展示分支、提交及合并检查基准，普通确认执行 `git branch -d -- <分支>`。不删除远端分支或工作区文件。当前或其他 worktree 占用（包括目录缺失的登记）、master、异常上游及进行中的任务/Git 操作会阻止删除。有 worktree 占用时可从弹窗转到“先释放对应 worktree”，释放后再删除分支。

确定不再需要未合并提交时，可在同一弹窗点击“强制删除…”。工具重新检查并展示相对同名上游或启动目录 HEAD 尚未合并的提交数及最多 80 条记录，点击“继续强制删除…”后还需在二次确认弹窗中确认，才执行 `git branch -D -- <分支>`。强制模式仅绕过未合并提交检查，保留 master、worktree 占用、仓库归属、异常上游及任务/Git 操作保护。不自动提交、推送或备份；没有其他引用保留的本地提交可能丢失。删除模式绑定预览，确认请求不能把普通删除升级为强制删除。

同名上游的本地引用已不存在时，普通删除仍停止检查；强制预览改用启动目录 HEAD 作比较，并显示实际检查基准，不自动 fetch。此提交列表只用于审查，不能据此断言提交已在远端备份。

删除预览 10 分钟有效且单次使用；执行前重查分支提交、上游、合并基准和占用，变化后重新预览，不自动重试。执行删除时须暂停其他工具对该分支的写入；重查和 Git 删除之间不能锁住外部 Git 客户端。检查使用现有本地远端引用，不自动 fetch。远端分支存在时，删除本地分支后列表仍可能显示同名的“仅远端”条目。实际删除与释放测试仅使用临时 Git fixture，本次开发不清理业务分支或 worktree。

## Windows 2026.11.04.3

`windows/` 提供 WinForms + WebView2 桌面入口、JSON 连接桥、NSIS 用户级安装器和白名单打包脚本。Python、psutil 和 .NET 随发行包提供；Git for Windows 与 WebView2 Runtime 由接收者准备，Node/JDK 按业务项目要求安装。首次选择自己的 Git 仓库，新 Windows 用户默认不关联飞书空间。安装与卸载不结束开发服务，升级前需要明确关闭空闲工作台后台和所有窗口；私有配置保留在 `%LOCALAPPDATA%\Branch Desk`。

跨平台适配集中在 `platform_support.py`：Windows SID/ACL 检查、文件锁、进程身份与目录检查、Git Bash/Node CLI 参数传递。Windows 服务停止为进程树终止，确认弹窗说明其不保证正常退出回调。桌面窗口关闭保留后台；窗口菜单可确认关闭空闲工作台后台，批量操作、冲突处理和需求读取期间拒绝退出。

后端状态通过目标 worktree 的 JVM 是否监听启动端口判断，不再要求 Gradle wrapper PID 自身监听；启动器 exec 后命令变化不使记录失效，但仍校验进程出生时间。仅端口存在不代表业务 API 或 SSO 已验收。Python 改动需要重启对应工作台后台，不能只刷新页面。

Windows 包已交叉构建与回归检查，未在 Windows 真机执行安装、卸载、运行或双端口 SSO 验收。具体分发步骤、Codex 排障模板及验收项见发行包内 `docs/Windows使用与Codex排障手册.md`。
